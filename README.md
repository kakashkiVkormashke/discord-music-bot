# Музыкальный бот Discord — Python 3.11

Бот может работать на нескольких серверах. На каждом сервере он слушает только один настроенный текстовый канал. Сообщения в других каналах игнорируются. Историю не читает, сообщения других ботов игнорирует.

Любое обычное сообщение в настроенном канале — запрос поиска YouTube. Также принимает «включи название», «поставь название», прямую ссылку на видео и ссылку на плейлист. В голосовом канале проигрывается только аудио. Поиск выбирает первый результат.

Плейлисты грузятся порциями, чтобы не забивать очередь и не грузить хостинг. По умолчанию первая ссылка на плейлист добавляет 25 треков. Когда они закончатся или когда захочется докинуть ещё, напишите «дальше», «ещё», «следующие», «загрузи дальше» или «докинь плейлист» — бот добавит следующую порцию из того же плейлиста.

Плейлисты достаются через yt-dlp. YouTube-плейлисты должны работать стабильно. VK, SoundCloud и другие сайты будут работать только если yt-dlp умеет достать этот публичный плейлист без входа в аккаунт и cookies.

Фразы управления: «включи следующий», «следующий», «скип»; «останови музыку», «стоп»; «пауза», «поставь на паузу»; «продолжи», «сними с паузы»; «очередь», «покажи очередь»; «дальше», «ещё», «следующие», «загрузи дальше», «докинь плейлист».

## Настройка канала на сервере

По умолчанию бот слушает канал из `TEXT_CHANNEL_ID`. Для старого сервера это `1429229290540503061`.

Чтобы настроить отдельный канал на новом сервере, напишите на этом сервере:

```text
lool channel_id
```

Пример:

```text
lool 123456789012345678
```

Команду может выполнить только участник с правом `Manage Server` или `Administrator`. Бот должен видеть канал с указанным ID. После настройки он будет слушать только этот канал на этом сервере.

Настройки сохраняются в `channels.json`. Если хостинг полностью пересоздаёт файловую систему при redeploy, команду `lool channel_id` после новой сборки может понадобиться повторить.

## Настройка Discord

1. Создайте приложение и бота в https://discord.com/developers/applications.
2. На странице Bot включите `Message Content Intent`.
3. Сохраните токен в переменную окружения `DISCORD_TOKEN` на хостинге. Не публикуйте токен в Git и не отправляйте в чат.
4. Пригласите бота с OAuth2 scope `bot` и правами `View Channel`, `Send Messages`, `Connect`, `Speak`.
5. Проверьте разрешения нужных текстовых и голосовых каналов на каждом сервере.

## Хостинг

Для Bothost.ru: в дополнительных настройках включите использование собственного `Dockerfile`. Без этого платформа может заменить Dockerfile автогенерируемым и не установить Deno.

Переменные окружения:

```text
DISCORD_TOKEN=токен_бота
TEXT_CHANNEL_ID=1429229290540503061
CHANNEL_CONFIG_PATH=channels.json
PLAYLIST_BATCH_SIZE=25
PLAYLIST_MAX_ITEMS=300
```

`TEXT_CHANNEL_ID` остаётся дефолтным каналом для серверов, где ещё не выполнена команда `lool channel_id`.

`PLAYLIST_BATCH_SIZE` — сколько треков добавлять из плейлиста за раз. Можно поставить 20 или 30. Больше 50 бот всё равно не возьмёт за одну порцию, потому что очередь ограничена.

`PLAYLIST_MAX_ITEMS` — сколько треков максимум бот запомнит из одного плейлиста. Это защита от огромных плейлистов.

Тип процесса — постоянный worker, без HTTP-порта. Запускать одну копию бота.

Без Docker на сервере должны быть Python 3.11, FFmpeg с libopus и Deno в PATH.

```bash
python -m pip install -r requirements.txt
python -u bot.py
```

## Проверка после запуска

Проверьте: `lool channel_id` сохраняет канал; сообщение в другом канале игнорируется; запрос без голосового канала получает подсказку; два запроса играют по очереди; пауза/продолжение работают; следующий переключает трек; стоп очищает очередь и отключает бота; ссылка на плейлист добавляет первую порцию; команда «дальше» добавляет следующую порцию.
